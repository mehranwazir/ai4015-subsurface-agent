# Failure analysis (final evaluation, test benchmark)

Generated by `python experiments/analyze.py` from the scored runs in `results/experiments/final/runs.csv` and the saved traces in `logs/evidence/final/`. A run fails when it is not task-correct.

## Failures of the proposed system (36 of 150 runs)

| Category | Failed runs | Distinct cases |
|---|---|---|
| G3: answered an interval above the error requirement | 12 | 4 |
| G3: refused an acceptable interval | 24 | 8 |

All failures of the proposed system are G3 acceptance errors; it made no G1 or G2 errors on the test cases. The outcome of every case was identical in all three repeats, so each failing case failed three times.

**G3: refused an acceptable interval.** The calibrated uncertainty limit (0.0254, chosen on validation wells to keep bad answers at or below 5%) is exceeded by intervals whose reference error is still within 0.05. Tree-ensemble spread is only a moderate predictor of error (Spearman 0.53 on validation windows), so a single limit cannot separate good and poor intervals cleanly. A looser limit admits more bad answers (see the risk-coverage curve, `results/final/figures/fig_g3_tradeoff.png`). Future work: per-well or interval-length aware calibration, conformal prediction intervals, and more validation wells.

**G3: answered an interval above the error requirement.** Some poor intervals have low tree spread: the forest agrees with itself but is wrong for that rock. Disagreement among trees cannot detect systematic error shared by all trees. Future work: input-distribution signals that actually track error on this field, or a second, independent predictor.

## Failures of the comparison systems

See `results/final/tables/failure_categories.csv` for counts per system. In short: B0 and B2 assume a unit when none is given, and B2's LLM reviewer approved most broken prediction files (silent errors), while the full system made neither error.

## Representative failure cases (proposed system)

### Failure 1: acceptable interval refused (G3 false refusal)

Run `final-full-test-predict-01-r1`, request: "Predict PHIF, SW and VSH for well 3 from 10600 to 10700 ft."

1. `inspect_dataset`  → ok
2. `inspect_interval` {"end": 10700, "start": 10600, "well": 3, "unit": "ft"} → ok (rows=305, input_coverage=1.0)
3. `predict_properties` {"slice_id": "slice-9232eace1f73ac7c"} → ok (rows=305, input_coverage=1.0, prediction_id=pred-c0789cd8e06cd512, uncertainty=0.0289 (decision abstain))
4. `finish` {"status": "abstain"} → ok (status=abstain)

Final: **abstain**, reason: "Model prediction abstained due to high uncertainty/out-of-range share (uncertainty: 0.0289 exceeds limit: 0.0254, out-of-range share: 5.57%).". 4 tool calls, 4 LLM requests.

Why it is a failure: the reference error of this interval is 0.0477, within the 0.05 requirement, so answering was the correct choice.

5. `predict_properties` {"slice_id": "slice-af8e3304f12fe96e"} → ok (rows=305, input_coverage=1.0, prediction_id=pred-0289f30bafc3af0a, uncertainty=0.0251 (decision answer))

Why it is a failure: G2 repaired the injected fault correctly, but the reported prediction has a mean property RMSE of 0.0985 against the reference labels, above the 0.05 requirement. Its uncertainty sat just under the limit, so G3 accepted it.
